# 플레이어 피격 효과

[전투 제작 안내](CombatFoundationGuide.md) · [검증 안내](ValidationGuide.md)

`PlayerMovement`가 초기화할 때 [PlayerDamageFeedback](../Scripts/Player/Combat/PlayerDamageFeedback.cs)을 자동 연결한다. 기존 씬과 플레이어 프리팹을 다시 설치할 필요 없이 실제 `PlayerDamageReceiver.ReceiveHit`의 `Damaged` 결과에 반응한다. 회피·가드·패링·무적·중복 공격에는 표시하지 않는다. 실드로 전부 흡수한 타격도 피격 효과가 나오며, 빈사 판정에는 HP만 사용한다.

## 화면 동작

- **월드 방향 아크**: 실제 공격 시작점의 3D 좌표를 피격마다 복사한다. 매 프레임 최종 카메라 위치·회전으로 방향을 다시 계산하므로 고개를 돌리거나 이동하면 크로스헤어 주변의 호가 공전한다. 앞은 위, 오른쪽은 오른쪽, 뒤는 아래다. 공격자가 이동하거나 삭제되어도 저장한 발사 위치를 유지한다.
- **독립 피격**: 각 타격이 자체 시간·강도·투명도를 가진다. 기본 1.65초 후 사라지며 새 피격이 이전 타격의 시간을 초기화하지 않는다. 최대 24개까지 동시에 표시하고 초과 시 가장 오래된 항목을 교체한다. 겹치는 아크는 세 개의 인접 반지름으로 분산한다.
- **혈흔 비네트**: 피격 방향 화면 가장자리에 부드러운 붉은 그라디언트가 번져 들어온다. 전용 셰이더 [PlayerDamageBlood](../Resources/Combat/Shaders/PlayerDamageBlood.shader)가 그라디언트에 피가 고르지 않게 스며든 얼룩을 넣고, 맞은 쪽 가장자리에만 바깥으로 튄 듯한 미세한 핏방울을 드문드문 뿌린다. 불투명한 덩어리는 없고 경계도 딱딱하지 않다. 얼룩·핏방울 배치는 깨끗한 화면에 새로 피가 묻을 때마다 바뀐다. 한 번 맞으면 맞은 쪽 가장자리만 붉어지고, 많이 맞아도 그라디언트는 화면 가장자리 약 20% 안쪽까지만 들어온다. 위·옆에서 맞으면 피격마다 가늘고 어두운 핏줄기 하나가 흘러내리고 끝에 방울이 맺힌다(아래쪽 피격은 흘러내리지 않음). 프로젝트가 Linear 색 공간이라 반투명 빨강이 분홍으로 바래는 문제를 셰이더에서 보정한다. 피는 화면에 고정되어 맞은 순간의 방향에 남는다. 0.16초 만에 번져 들어와 1.6초 유지하고, 3.4초에 걸쳐 가장자리로 물러난다. 연속 피격은 서로 겹쳐 더 깊이 들어온다. 뒤쪽 피격은 하단 혈흔과 화면 전체의 옅은 붉은 막을 함께 적용한다. 방향을 알 수 없는 낙하 피해는 사방 테두리에 번진다. 피격별 GameObject·재질·이미지 없이 혈흔 32개·핏줄기 24개 풀을 재사용한다.
- **카메라**: 별도의 피격 트라우마를 누적하고 `Trauma² × Shake Max Angle`로 흔들림을 계산한다. 방향에 따른 짧은 롤·피치 킥을 기존 `CameraViewPunch`에 합성한다. 다음 프레임 게임플레이 처리 전에 시점을 복원하여 조준·총알 판정에 시각 오프셋이 누적되지 않는다. 피격 채널을 정리해도 사격 반동 스프링은 유지한다.
- **부상·빈사**: HP 50% 아래부터 사방 테두리에 옅은 혈흔이 계속 남고, HP가 낮을수록 짙어진다. `HP / MaximumHealth <= 0.25`에서는 부드러운 붉은 비네트가 **항상 켜진 채로** 유지된다. 심장이 "쿵-쿵" 두 번 뛸 때마다(기본 58 BPM) 비네트가 순간적으로 안쪽으로 조여 들며 진해졌다가 천천히 풀리고, 가장자리 혈흔도 함께 밀려 들어온다. 박동 사이에도 비네트는 사라지지 않는다. 회복·최대 HP 변경을 매 프레임 반영한다. 25%를 넘으면 박동은 즉시 멈추고 남은 혈흔은 천천히 빠진다.

효과는 `EFFECTS → Screen → Player Damage Feedback`의 독립 Overlay Canvas(순서 24, 기준 1920×1080)에 표시된다. 마우스 입력을 가로채지 않는다. 완전 일시정지에서는 피격 수명·쉐이크·박동을 멈추고, 전투 슬로모션에서는 실제 시간으로 감쇠한다. 사망·부활·컴포넌트 비활성화 시 혈흔과 피격 채널을 정리한다.

## 조절 위치

[Resources/Combat/PlayerDamageFeedback.asset](../Resources/Combat/PlayerDamageFeedback.asset)을 선택한다. Play를 종료하고 수정해야 영구 저장된다.

| 항목 | 조절 내용 |
| --- | --- |
| Layers | 방향 아크·혈흔 비네트·피격 쉐이크·부상/빈사 각각 켜기/끄기 |
| Independent Hit Arcs | 수명, 유지 구간, 반지름, 두께, 각도, 색 |
| Blood Vignette | 짙은 피·신선한 피 색, 타격당 혈흔량, 그라디언트 강도·최대 진입 범위, 미세 핏방울 밀도, 유지·소멸 시간, 신선한 색 지속, 얼룩 노이즈 크기, 타격당 핏줄기 수·최대 길이·흐르는 시간, 뒤쪽 전체 막 |
| Damage Camera Channel | 피격 트라우마, 최대 흔들림 각도, 회복 속도, 주파수, 방향 킥 |
| Low Health | 부상 혈흔 시작 HP·최대량, 빈사 HP 비율, 빈사 상시 혈흔량, 박동당 밀려드는 양, BPM, 빈사 붉은 비네트 강도 |

총기 타격감 설정의 `GunFeel → View Punch`와 피격 쉐이크 스위치는 독립적이다.

## 바로 시험하기

CombatFoundation을 Play하고 Enter로 채팅을 연다.

| 명령 | 확인 |
| --- | --- |
| `/hit 10 left` | 왼쪽 아크·왼쪽 가장자리에서 번져 드는 혈흔 |
| `/hit 10 right`, `/hit 10 front`, `/hit 10 back` | 네 방향 비교. 뒤쪽은 아래 아크·하단 혈흔·전체 붉은 막 |
| `/hit 5 left` 후 `/hit 5 back` | 각 아크가 동시에 남았다가 개별 소멸 |
| `/revive` 후 `/hurt 75` | 기본 최대 HP 100에서 25 HP 빈사 박동 |
| `/heal`, `/revive` | 빈사 해제 / 부활·모든 피격 효과 정리 |

`/hit`은 실제 공격 피해 경로를 사용하므로 회피·처형 무적 중에는 피해가 방지될 수 있다. 채팅을 닫고 마우스를 크게 돌리면 남은 아크가 최초 피격의 월드 위치를 따라 움직인다. 회전 확인 시간을 늘리려면 잠시 `Hit Seconds`를 늘린다. `/hurt`는 기존처럼 회피를 무시하는 방향 없는 시험 피해다.

## 새 공격 연결 계약

[DamageHit](../Scripts/Combat/Damage/DamageHit.cs)의 마지막 선택 인자 `origin`에 **발사 시점의 월드 좌표**를 전달한다. 히트스캔 [AttackTrace](../Scripts/Combat/HitDetection/AttackTrace.cs)는 명시한 `Origin`을 보존하며, 없으면 레이 시작점을 전달한다. 투사체는 충돌 시점의 투사체 좌표 대신 발사 때 저장한 총구 좌표를 넘겨야 한다.

직접 접촉하는 기존 공격은 `Source.transform.position`을 피격 시 복사한다. `Source`와 `Origin`이 모두 없는 기존 공격은 역방향 광선 30m 지점을 대체 위치로 사용하므로, 정확한 이동 추적이 필요한 신규 공격은 반드시 `origin`을 지정한다.

## 직접 확인할 것

CombatFoundation에서 적에게 맞으면서 확인한다. 피격 방향 아크가 공격자를 따라가는지(맞은 뒤 180도 돌아도), 여러 방향에서 동시에 맞을 때 각각 따로 사라지는지, 화면 중앙이 가려지지 않는지, 체력 25% 아래에서 빈사 박동과 가장자리 혈흔이 유지되는지, 회복·사망·재시작 때 효과가 정리되는지 본다. 그 밖의 확인 순서는 [검증 안내](ValidationGuide.md)를 따른다.
