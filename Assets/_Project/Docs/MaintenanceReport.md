## 정리한 내용

- 루트 README를 시작 안내와 문서 목차의 기준으로 만들고, `Assets/_Project/README.md`는 Unity 창에서 찾을 수 있는 짧은 진입점으로 줄였다. 문서의 프로젝트 안내 링크도 루트로 연결했다.
- 문서와 무기 데이터 생성 메뉴를 ENFILADE로 맞췄다. 폴더 이동 후 여는 방법, 설정 저장 위치, Resources 로드 키, 현재 구현과 후속 기획을 안내했다.
- 채팅·목표판 입력 검사를 Edit Mode로 실행하라는 잘못된 안내를 Play Mode로 고쳤다. 실제 채팅·웨이브·HP·궁극기 자원 테스트 명령을 전투 제작 안내에 추가했다.
- `Tools/Test-ProjectStructure.ps1`로 문서 상대 링크·누락/고아 메타데이터·중복 GUID를 확인할 수 있게 했다. `Tools/Validate-Project.ps1`는 현재 파일을 새 복사본에 넣고 Unity 검사를 실행하며 결과와 로그를 기록한다. `ProjectChecks.RunEditMode`는 기존 이동·전투·HUD 검사를 한 번에 실행한다.
- 총구 주변 충돌 조회를 32칸 재사용 버퍼로 바꿔 일반 경로의 결과 배열 할당을 없앴다. 자기 콜라이더가 버퍼를 채워 장애물을 놓칠 수 있으면 전체 조회로 다시 확인한다. 40개 자기 콜라이더·작은 외부 장애물·소유자 없음·장애물 제거를 검증에 추가했다. FPS나 전체 발사의 무할당을 측정한 변경은 아니다.
- 예전 회피 거리 2m를 기대하던 검사를 현재 설정값 참조로 고쳤다. 슬라이딩 자세별 검사는 이미 넘어진 적 대신 새 표적을 사용한다. 재로드 검사는 장비를 내린 현재 씬에서 첫 무기를 명시적으로 선택한다. 게임의 회피 거리·시작 슬롯·넘어짐 규칙은 이 검사에 맞추어 바꾸지 않았다.
- `DefaultVolumeProfile.asset`의 누락된 효과 4개와 패키지 테스트 전용 컴포넌트 5개를 제거했다. 남은 실제 볼륨 컴포넌트 **19개의 값은 원본과 동일**하다. `PC_Renderer.asset`에서는 현재 패키지에서 폐기된 probe 디버그 리소스 참조 7개를 제거했다. 두 파일의 GUID는 유지했다.
- 자동 생성된 `UpgradeLog.htm`, `UpgradeLog2.htm`을 삭제하고 재생성 로그와 `.validation`을 Git에서 제외했다. 앞 작업에서 붙어 있던 HUD 코드의 줄바꿈도 정리했다.

수치의 원본은 기존 Unity 씬·프리팹·ScriptableObject다. 별도 Excel 원본은 추가하지 않았다. 편집 위치와 적용 범위는 [설정·유지보수 안내](MaintenanceGuide.md)를 따른다.

## 후속: EFFECTS·ENEMIES 통합과 혈흔 풀 유지

효과는 이전 SYSTEM·UI 아래의 런타임 분류 대신 전용 `EFFECTS`로 통합했다. `Audio`에는 총성·피격음, `World`에는 총구 효과·Impact VFX·시체 연출, `Screen`에는 피해 숫자·히트마커·처치 피드·처치 화면 효과가 생성된다. 빈 폴더에는 Canvas나 게임 로직을 추가하지 않아 기존 화면 표시와 월드 위치를 유지한다.

적은 `ENEMIES → Console / Waves`로 정리했다. `RuntimeSceneHierarchy`가 소유 씬에서 분류를 만들거나 재사용한다. 장식형 제목을 인식하면서 `Console Enemies`를 `ENEMIES` 자체로 잘못 인식하지 않도록 전체 이름을 비교한다. 콘솔 적은 웨이브 추적 목록에 추가하지 않는다.

최적화와 안정성을 우선해 혈흔의 **기존 최대 32개 재사용 풀을 유지**했다. 수명과 페이드가 끝나면 비활성화하며 다음 타격에서 같은 오브젝트를 재사용한다. 생성 위치는 `EFFECTS → World → Impact VFX → Blood Decals (Pool)`이다. 비활성 혈흔이 보이는 것은 대기 중인 고정 크기 풀이며 개수가 무한히 늘어나는 구조가 아니다. 수명·재사용 규칙을 바꾸는 대신 풀을 별도 폴더로 묶었다.

별도 복사본의 계층 통합 검증에서 **9개 검사 묶음이 모두 통과**했다. 풀을 유지하는 최종 상태에서는 `GunFeelPlayChecks.RunBatch`를 추가 실행해 통과했다. 64번의 혈흔 생성에도 32개 상한을 유지하고, 만료 후 비활성화한 동일 오브젝트를 새 혈흔에 재사용하며, 재사용 후에도 다시 풀로 돌아가는 것을 확인했다. 원래의 발사·명중·처치·화면 복구 검사도 통과했다.

콘솔·웨이브 실제 NavMesh 소환, 공통 분류와 각 하위 폴더, 웨이브 추적 수, 일시정지·재개·중단, 중단 후 콘솔 적 유지도 확인했다. 문서 11개·에셋과 폴더 646개·GUID 646개에 대한 구조 검사와 `git diff --check`도 통과했다.

로컬 기록은 `.validation/20261026-194357-073a0db9/results.json`, `final-pool-results.json`, `source-hashes.json`과 `Logs` 폴더다. 최종 풀 검사의 완료 문구는 `BLOOD_DECAL_POOL_CHECKS_PASSED`, 적 분류 검사는 `ENEMY_HIERARCHY_CHECKS_PASSED`다. 임시 Unity 복사본은 검증 후 휴지통으로 옮기고 기록만 보관했다. Play를 종료하고 다시 시작하면 새 분류가 필요한 시점에 자동 생성된다.

## 후속: 적을 벽·렛지로 인식하는 문제 수정

벽·렛지 탐지가 적의 충돌체를 일반 지형으로 받아들이던 경로를 수정했다. 기존 회피용 적 식별 규칙(상위 `MeleeCombatTarget`·`EnemyHealth` 또는 Enemy 태그)을 공유해 자식 콜라이더도 제외한다. 벽 접촉·렛지 탐지·옆 이동과 진행 중인 지지면을 확인하며, 적으로 바뀐 지지면에서 새 점프 입력으로 벽차기나 렛지 이동을 이어갈 수 없게 했다.

일반 장애물 탐지·머리 위 발판·충돌 레이어는 유지했다. 따라서 적 머리를 넘어가는 Vault와 머리 위로 올라서는 짧은 통과 경로는 그대로 사용할 수 있다. 후자는 내부 상태명이 Mantle인 Vault1 경로도 포함한다.

별도 복사본에서 `EditMode`, `Defense`, `Reload`를 실행해 **모두 통과(종료 코드 0)**했다. 새 6개 회귀 검사 그룹은 부모 태그·컴포넌트와 자식 콜라이더, 진행 중 태그 변경·재부모화, 새 점프 입력 우회 차단, 머리를 넘는 경로와 올라서는 경로의 보존을 다룬다. 전체 이동 기능 검사 96개 그룹과 기존 정상 벽·렛지·전투·HUD 검사, 실제 Play Mode 방어·회피 및 어셈블리 재로드 검사도 통과했다.

문서 11개·에셋과 폴더 647개·GUID 647개의 구조 검사와 `git diff --check`도 통과했다. 로컬 검증 기록은 `.validation/20261026-201646-e43904d3/results.json`, `source-hashes.json`, `Logs` 폴더다. 임시 Unity 복사본은 검사 후 휴지통으로 옮기고 기록만 보관했다. 기존 작업 변경과 사용자 프로젝트 설정 변경은 그대로 유지했다.

## 2026-10-27 사운드·근접 전투와 최종 점검

Unity **6000.3.12f1**, Windows에서 현재 작업 파일을 복사해 전체 검사와 에셋 참조 점검을 실행했다. 커밋과 스테이징은 하지 않았다.

### 반영 사항과 구조 점검

- 주먹 공격 소리는 `Combat/Player/Attack/Punch/Swing`, `Hit`, `Wall`, 플레이어 피격 소리는 `Combat/Player/Damage/Hit`으로 구분했다. 이동한 오디오 파일의 GUID와 내용은 유지했고, 옛 경로의 빈 폴더·잔여 메타데이터를 정리했다.
- 벽 타격음 10개를 `Feedback.asset`의 `Punch Wall Sounds`에 연결했다. 주먹의 적·벽 접촉은 후딜을 즉시 해제하고, 허공 후딜 기본값은 0.4초에서 0.2초로 줄였다. 벽 소리는 한 공격당 한 번 재생하고 직전 변형의 반복을 피한다.
- 공통 근접 스윕·밀치기의 대상별 가림 검사와 벽 접촉 시 공격 종료 조건을 제거했다. 반격의 가림 검사도 제거했다. 사거리·전방 범위·대상 수 제한·공격 ID에 의한 중복 방지는 유지한다. 총기와 실제 몸 이동·V 홀드 접근·처형의 충돌/가림 규칙은 별도다.
- 사운드 폴더와 배열 연결 방법을 [설정·유지보수 안내](MaintenanceGuide.md)에 추가했다. [전투 규칙](WeaponSystemDesign.md)과 [검증 안내](ValidationGuide.md)도 현재 후딜·벽 소리·총기/근접 규칙에 맞췄다.
- `git diff --check`가 찾은 씬·HP HUD 프리팹의 빈 `m_Name` 필드 공백 3곳을 제거했다. 필드 값은 빈 문자열로 동일하다.
- 추가 구조 변경이 필요한 결함은 이번 코드 점검에서 발견하지 못했다. 혈흔 최대 32개·탄피 최대 24개 풀, 피격 UI 고정 배열, 캐시된 리소스와 연결된 HUD의 탐색 중단을 확인했다. 근접 벽 무시를 위해 별도 장애물 우회나 추가 물리 검사를 넣지 않았다.

### 실제 실행 결과

`Tools/Validate-Project.ps1 -All`의 **11개 묶음이 모두 종료 코드 0과 각 완료 문구를 기록**했다.

| 검사 | 결과 | 주요 확인 |
| --- | --- | --- |
| `EditMode` | 통과 | 이동 기능 96개 그룹, 무기·주먹/슬롯 23개 그룹, HUD·체력·채팅 |
| `Slide` | 통과 | 30/60/120Hz 접촉·적 크기·레그돌·벽과 실제 이동 |
| `Defense` | 통과 | 벽 적중 연타·벽 소리, 근접 벽 무시, 방어·반격·회피·정리 |
| `Execution` | 통과 | 군중 처형·NavMesh·물리적 엄폐·밀침·복구 |
| `Ranged` | 통과 | 실제 씬 총기·총구 안전·탄약·조준·화면 캡처 |
| `GunFeel` | 통과 | 총성·피격·처치 효과·후처리 복구 |
| `DamageFeedback` | 통과 | 방향 추적·혈흔 셰이더 출력·빈사 표현·정리·화면 캡처 |
| `Ammo` | 통과 | 탄약·장전 HUD |

| `Ultimate` | 통과 | 궁극기 스탯·최대 보유량·소비량·HUD·콘솔 |
| `Reload` | 통과 | 실제 Play Mode 어셈블리 재로드 후 상태 복구 |

열린 CombatFoundation 씬의 Play Mode에서도 기존 `MissionInputChecks` 요청 훅으로 입력 검사를 실행해 `MISSION_INPUT_CHECKS_PASSED`를 확인했다. 목표판 TAB 열기, 채팅 중 TAB 채널 전환, 숨겨진 입력 선택 해제, 게임 입력 맵 복구, 활성화/비활성화 후 단축키 복구를 다룬다. 검사 후 Play Mode를 종료했다.

구조 검사는 PowerShell 7과 Windows PowerShell 5.1에서 모두 통과했다. 문서 **12개**, 에셋·폴더 **699개**, GUID **699개**다. 패키지 메타데이터를 포함한 별도 참조 점검에서 프로젝트 직렬화 파일 **62개**의 GUID 참조 **1,465개** 중 미해결 참조는 **0개**였으며, 오디오 참조 **70개**도 포함한다. 리소스 설정·셰이더 로드 키 6개가 각각 한 에셋에 연결됨을 확인했다.

검사 전 원본과 복사본의 비문서 파일 **998개**가 SHA-256으로 일치했고, 검사와 실제 에디터 입력 확인 후에도 원본 해시가 동일했다. 생성된 피격 방향·빈사 효과·총기 벽 앞 자세 이미지를 직접 열어 확인했다.

### 남은 범위와 로그

게임 검사 예외·C# 컴파일 오류/경고·셰이더 오류는 최종 배치 로그에서 발견되지 않았다. 다만 `UnityEditor.Search.SearchInit.IndexationOnStartup`의 **기존 검색 인덱서 시작 예외가 7회** 기록됐다. `Execution`, `GunFeel`, `DamageFeedback`, `Ultimate`, `Reload` 로그에 있으며, 모두 같은 에디터 검색 스택이다. 검사 완료 및 종료 코드와 구분해 기록하며, 에디터 전체의 무오류를 뜻하지 않는다.

활성 근접 스윕의 `SphereCastAll`/`OverlapSphere`에는 결과 배열 할당이 남는다. 이번에는 FPS·GC 할당량을 프로파일링하지 않았다. 밀집 전투에서 병목이 측정되면 재사용 버퍼와 포화 시 누락 방지를 함께 검토한다. 현재의 정확한 전체 조회를 복잡한 버퍼 처리로 바꿀 근거는 이번 점검에서 확보하지 못했다.

로컬 기록은 `.validation/20261027-022918-3669487e` 아래 `results.json`, `source-hashes.json`, `asset-reference-audit.json`, `log-audit.json`, `mission-input-result.txt`, `Logs/*.log`, `Screenshots/*.png`다. 생성 이미지 18개도 별도 보관했다. 검증 복사본의 재귀 삭제는 자동 승인 검토가 `blocked by policy`로 차단해, 이번 전체 검사와 직전 근접 검사에서 만든 임시 프로젝트·캐시는 `.validation`에 남아 있다. 로그·이미지·복사본은 모두 Git에서 제외된다. 실제 입력 검사는 키보드 상태를 주입한 회귀 검사이며, 장시간 플레이 조작감 평가를 대신하지 않는다.
