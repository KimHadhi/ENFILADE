# 전투 규칙과 확장 계획

[프로젝트 안내](../../../README.md) · [설정·제작 방법](CombatFoundationGuide.md) · [전투 코드 구조](../Scripts/Combat/README.md) · [검증 안내](ValidationGuide.md)

현재 구현된 전투 규칙과 후속 기획을 구분해 정리한다. 아래 수치는 별도 표기가 없으면 기본값이다. 실제 플레이에서는 [밸런스 표](MaintenanceGuide.md#밸런스-표-data-tables)의 값이 우선하고, 표에 없는 값은 씬·프리팹·설정 asset의 Inspector 값이 우선한다.

## 1. 슬롯과 무기 상태

| 키 | 슬롯 유형 | 빈 슬롯을 선택했을 때 |
| --- | --- | --- |
| 1 / 2 | 원거리 | 주먹 사용 |
| 3 | 근접 | 주먹 사용 |
| 4 | 특수 | 주먹 사용 |

- 주먹은 별도 아이템으로 저장하지 않는다. 선택한 슬롯이 비어 있으면 사용한다.
- 같은 숫자를 다시 누르면 선택을 해제한다. 이때 총·주먹 표시와 좌·우클릭 주먹 전투를 끈다. `Starting Slot = 0`도 해제 상태를 뜻한다.
- `SelectSlot(index)`는 명시적 선택, `SelectSlot(-1)`은 해제, 숫자 입력과 `ToggleSlot`은 선택·해제 토글이다. 런타임 인덱스는 0부터 시작한다.
- 각 슬롯은 독립된 `WeaponRuntime`을 보관한다. 탄창·예비탄은 전환과 컴포넌트 재활성화 뒤에도 유지하며, 전환할 때 진행 중인 장전·차징·가드를 취소한다.
- `TrySetWeapon`은 슬롯 유형을 검사한다. `TryAcquire`는 호환되는 빈 슬롯을 우선 사용하고, 없으면 현재 선택한 호환 슬롯만 교체해 밀려난 데이터를 반환한다.

데이터 교체 API는 구현되어 있다. 실제 필드 아이템·줍기·드롭 연출은 후속 작업이다.

## 2. 원거리 전투

### 조준과 총구 안전성

카메라 중앙의 첫 유효 표면을 조준점으로 삼고, **실제 총구에서 히트스캔을 발사**한다. 총구와 조준점 사이의 벽이 피해를 막는다. 총구 뒤쪽의 조준점, 과도한 근접 수렴, 총구 매몰, 카메라와 총구 사이의 장애물을 감지하면 high-ready 자세로 올리고 발사·탄약 소모·ADS를 차단한다.

총을 올리고 내리는 자세는 부드럽게 전환하지만 엄폐와 발사 차단은 즉시 적용한다. 우클릭을 유지하고 장애물에서 벗어나면 총을 내린 뒤 ADS로 돌아간다. 연사 중에도 격발마다 총구 안전성을 다시 확인한다.

- `WeaponPresentation`은 모델 자세와 가까운 표적↔먼 표적 사이의 수렴을 보간한다. `Aim Follow Half Life`, `Ads Aim Follow Half Life`로 반응을 조절한다.
- `WeaponAimSolver`의 실제 명중·엄폐 판정은 그 시각 보간을 사용하지 않는다. 마우스 회전과 Q/E 입력에도 별도 지연을 넣지 않는다.
- 새 모델의 총구는 로컬 +Z가 전방이어야 한다. 모델이 없는 시험용 컨트롤러는 카메라 위치를 발사 원점으로 사용한다.

### 발사·탄약·장전

| 항목 | 규칙 |
| --- | --- |
| 단발 | 새 클릭마다 한 발. 쿨타임 중 누른 클릭을 뒤늦게 재생하지 않음 |
| 연사 | 누르는 동안 발사 간격을 누적해 처리. 긴 프레임의 몰아 쏘기는 프레임당 최대 4발 |
| 점사 | 클릭당 Burst Count발. 버튼을 놓아도 시작한 점사는 완료하며 점사 사이 Burst Pause 적용 |
| 탄약 | 무기 인스턴스마다 탄창과 유한 예비탄 보관. `WeaponData`에 현재 잔탄을 저장하지 않음 |
| 재장전 | R로 시작. 잔탄이 있으면 Reload Duration, 비었으면 Empty Reload Duration 사용 |
| 탄약 이동 | 장전 완료 순간 한 번만 이동. 예비탄 부족 시 가능한 만큼만 채움 |
| 자동 장전 | 탄창이 비고 예비탄이 있으면 다시 쏠 수 있게 된 뒤 0.2초에 저절로 장전한다(ArcCW의 `arccw_automaticreload`, [Weapons.csv](../Resources/Tables/Weapons.csv) `autoReloadDelay`, 0보다 작으면 끔). R을 누른 것과 같아서 회피·넘기·밀치기 중이면 끝난 뒤에 시작한다 |
| 잔탄 경고음 | TFA 베이스의 `EmitLowAmmoSound`(쏜 사람만 듣는다). 쏜 뒤 탄창이 3분의 1 미만(`lowAmmoFraction` 0.33)이면 총마다의 경고음이 나고, 비어 갈수록 커진다(1 − 남은 비율 ÷ 0.33, 총소리 크기 기준). 탄창을 비우는 마지막 발은 경고음 대신 총마다의 마지막 발 소리다. 경고음과 함께 CS2의 딸깍이 난다(SoundCues `GunLowAmmoClick/<총>`, 총소리보다 0.05초 늦게). 사용자가 2026-11-06에 들어 보고 고른 D(TFA 경고음 + CS2 딸깍)다. TFA처럼 4발 이하 탄창은 경고음이 없고, 그 탄창은 마지막 발에 빈 탄창 소리가 난다(`lowAmmoSmallMagazine` 4). 소리 파일과 크기는 소리 세션 몫이다(`Art/Audio/Guns/<총>/LowAmmo`·`LastRound`, `Guns/LowAmmoClick`). 그 전 규칙은 레포데 애드온 Low Ammo Sound Cue(3198155663)의 "20%(올림), 적어도 3발 이하면 매 발 같은 딸깍"이었다 |
| 취소 | 회피·무장 밀치기·슬롯 전환·사망·입력 차단 등이 장전과 남은 점사를 정리 |
| 일시정지 | 시간 배율 0에서는 발사·장전 타이머 정지 |

기존 무기에 탄약을 지급할 때는 `WeaponRuntime.AddReserve`를 사용한다. 무기를 새 데이터로 교체하는 것과 예비탄을 보충하는 것은 서로 다른 작업이다.

### 관통과 도탄

Horde가 쓰는 ArcCW 무기 베이스(워크숍 2131057232)의 `DoPenetration`과 `GetRicochetChance`를 옮겼다([BulletPenetration](../Scripts/Combat/HitDetection/BulletPenetration.cs), `AttackTrace.Bullet`).

| 항목 | 규칙 |
| --- | --- |
| 관통력 | 총마다 [Weapons.csv](../Resources/Tables/Weapons.csv)의 `penetration`(ArcCW의 mm). 소총 20, 권총 8: Horde의 M4A1 10, G17 4를 관통이 세게 느껴지도록 두 배로 올렸다(223). 얇은 콘크리트벽 뒤에 소총 피해가 약 70%, 나무벽 뒤에 약 80% 남고, 줄지어 선 좀비 여럿을 뚫는다. 0이면 처음 맞은 곳에서 멈춘다 |
| 뚫고 나가기 | 맞은 것 안으로 4단위(약 10cm)씩 나아가며 한 걸음마다 4 × 재질 계수만큼 관통력이 줄고, 걸음마다 5%씩 더 든다. 아무리 얇아도 두 걸음은 들고, 걸음마다 조금씩 빗나간다 |
| 재질 계수 | [Surfaces.csv](../Resources/Tables/Surfaces.csv)의 `penetration`, 없으면 부모 표면 것(ArcCW.PenTable: 금속 1.5, 콘크리트 0.75, 나무·흙·타일 0.5, 모래 0.25, 유리 0.025). 지형이 아닌 것(몸, 소품, 피해를 받는 것)은 1.5배 단단하다. 적·플레이어·시체는 `Flesh` 0.03이다. ArcCW의 0.1은 몸 모양 히트박스(약 25cm)를 뚫는 값인데, 지금 좀비는 지름 1m 캡슐이라 같은 값이면 한 몸에 관통력이 절반 넘게 들어 뒤 좀비에게 피해가 절반쯤밖에 가지 않았다(2026-11-06 사용자 테스트). 3분의 1로 낮추면 캡슐 한가운데를 뚫어도 ArcCW가 사람 하나에 쓰는 만큼(약 2.6) 든다. 줄지어 선 좀비를 소총으로 쏘면 하나 지날 때마다 피해가 약 87%, 74%, 62%, 49%로 남고, 권총은 68%, 36%다. 좀비에 뼈 히트박스가 생기면 0.1로 되돌린다 |
| 남는 피해 | 빠져나오면 남은 관통력 ÷ 총의 관통력만큼 피해와 체간 피해가 남는다. 한 발이 같은 대상에게는 한 번만 피해를 준다 |
| 도탄 | 정면은 0%, 표면과 나란할수록 min(남은 관통력 × 재질 계수 × 2, 45)%까지. 튕기면 거울처럼 반사되고 각도에 따라 몇 도 빗나가며 관통력은 25~95%가 남는다. 소리는 ArcCW의 `ricochet01`~`05` |
| 뚫고 나온 쪽 | 벽 뒷면에서는 그 표면의 이펙트가 `exitScale`(1.3~1.8)배로 커지고 면과 총알 방향의 중간으로 터지며, `exitPresets`의 파편·불꽃이 더해지고 탄흔도 그만큼 크다([ImpactEffects.csv](../Resources/Tables/ImpactEffects.csv), `ImpactPool.PlayExit`). 몸을 뚫으면 등 뒤로 `BloodExit` 피가 총알 방향으로 뿜어지고 뒤에 핏자국이 남는다(`ImpactVfx.ExitWound`) |
| 관통 소리 | 벽을 뚫을 때 들어간 자리에서 재질 소리가 난다. `Bullets` 사운드 뱅크의 `Art/Audio/Bullets/Penetrate/<표면>` 폴더를 표면의 부모 순서로 찾고, 클립이 없으면 소리가 없다 |
| 관통 표시 | 첫 명중 뒤의 구간(벽·몸을 지났거나 튕긴 뒤)에서 맞힌 피해는 `DamageHit.Pierced`가 켜진다(`AttackTrace.Bullet`). 처치면 "관통 사살" 점수가 붙는다(아래 점수). 히트마커는 각 선 바깥으로 흐린 꼬리가 뻗는다(아래 히트마커와 점수) |
| 다른 PC | 무작위를 발사 위치와 방향에서 정하므로 친구 PC도 같은 길을 그린다. 벽 뒷면 탄흔과 파편, 등 뒤 피, 그다음 명중의 이펙트와 피, 이어지는 궤적, 관통·도탄 소리 |

Unity에 맞춘 차이: 벽 두께는 들어간 선을 따라 한 번 잰다. 이어서 맞닿은 지형(또는 같은 몸)은 하나로 친다. 다음 탄은 ArcCW처럼 마지막 걸음 끝(뒷면에서 4~8단위 뒤)이 아니라 벽 뒷면에서 출발한다. Unity의 레이는 시작점이 이미 들어가 있는 충돌체를 보지 못해서, 벽에 붙어 선 적을 놓치지 않으려는 것이다. 한 면만 있는 평면 충돌체는 뒷면을 찾을 수 없어 뚫리지 않는다.

### 정확도·반동·ADS

- **탄퍼짐**은 도 단위의 원뿔 반각이다. Hip / ADS / Moving / Airborne Spread와 발사 후 Bloom을 합성하며, 크로스헤어도 실제 각도와 FOV를 반영한다.
- **앉아 쏘기**: 땅 위에서 앉아 있으면 탄퍼짐 전체에 `crouchSpread`(0.5), 조준 반동에 `crouchRecoil`(0.65)을 곱한다. 규칙은 ArcCW의 `arccw_mult_crouchdisp`·`arccw_mult_crouchrecoil`(기본 1이라 꺼져 있다)이고 값은 TFA 베이스의 기본값이다. 지향·조준·이동·연사 누적에 모두 들어가며 엎드림·슬라이드에는 들어가지 않는다.
- **총 흔들림**([WeaponSway](../Scripts/Player/Combat/Weapons/WeaponSway.cs)): 세기는 Weapons.csv의 `lookSway`·`moveSway`(1)다.
  - 움직임과 걸음: ArcCW 뷰모델 흔들림(`cl_viewmodel.lua`의 Move·Step 처리)이다. 움직이면 몸을 따라 기울고, 걸으면 걸음마다 출렁인다. 걷기 속도(Player.csv `Move.walkSpeed` 4.9m/s)를 넘으면 넘는 만큼의 30%만 출렁임에 더하고, 슬라이드 중에는 걸음 출렁임이 없다.
  - 시선 돌리기: TFA 베이스(워크숍 2840031720)의 Sway(`client/viewmodel.lua`)다. 총이 회전에 끌려가듯 늦게 따라오고(총구가 가장 많이 처진다), 회전이 멈추면 제자리를 조금 지나쳤다가 돌아온다. 120°/s로 돌면 약 2° 처지고, 축은 눈앞 약 30cm다. 조준하면 15%만큼, 그 두 배 앞을 축으로 흔들린다.
  - 숨쉬기: ArcCW의 Breath 처리를 바로 세웠다. 들이쉬는 동안 총이 오르며 총구가 들리고, 내쉬며 가라앉았다가 잠깐 쉰다. 주기는 π초, 높이는 ±2.5mm로 ArcCW와 같다.
  - ArcCW에서 바꾼 까닭(2026-11-06 사용자 테스트): ArcCW의 시선 흔들림은 총을 도는 쪽으로 돌려서, 반대로 밀리는 것을 거의 상쇄해 고개를 돌린 느낌이 나지 않았다. 걸음 출렁임은 속도에 비례하고 질주에서 더 커져(×1.25, sextra) 몸의 달리기 위에서 우스꽝스러웠다. 숨쉬기는 총이 오를 때 총구를 숙여 내려가는 것처럼 보였다.
  - 공통: 조준하면 거의 사라진다. 표시만 바꾸므로 그 프레임의 발사와 엄폐 판정을 마친 뒤 눈을 중심으로 총을 옮기고, 총알은 그대로 조준선으로 간다. 자기 총만 흔들린다. 두 베이스 모두 프레임마다 돌므로 여기서는 1/66.66초 단위로 돌려 프레임률과 상관없이 같게 보인다. ArcCW 원본은 첫 조준 뒤 숨쉬기가 영영 멈추는 버그가 있어 조준 중에만 줄도록 고쳤다. 시선은 카메라 흔들림 없이 조준 방향(마우스와 반동)만 읽는다.
- **조준 반동**은 실제 조준 방향에 적용된다. Recoil Pattern의 x는 상향, y는 좌우이며 배열을 반복한다. 배열이 없으면 Recoil Per Shot을 사용한다. 응답 속도와 남는 상승량은 Recoil Response / Retention으로 조절한다.
- **화면 킥**은 Gun Feel의 시각 효과다. 실제 조준 반동과 별도이며, 효과 때문에 히트스캔·엄폐 판정이 달라지지 않게 되돌린다.
- **헤드샷**은 총알 피해에 배율을 적용한다. `WeaponHitRegion`의 Head / Body 지정이 우선하고, 현재 단순 적 캡슐은 상단 22%를 머리로 취급한다. 부위 콜라이더는 일반 콜라이더를 사용한다.
- **ADS**는 견착·FOV·지상 이동 배율을 함께 바꾼다. 진입부터 줌 해제가 끝날 때까지 크로스헤어를 숨기고 기존 프로필은 보존한다.
- **Q/E 마이크로 회피**는 ADS와 장전을 유지한다. 일반 스텝 회피는 조준과 장전을 끊는다. 기울이기 중 상체 피격 볼륨은 옆으로 움직이며 이동용 캡슐과 하체는 제자리에 남는다.

## 3. 주먹·밀치기·돌진 밀치기

빈 슬롯을 선택한 상태에서 주먹 전투를 사용한다. 주먹은 [몸의 손](PlayerBodyGuide.md#몸의-손)이 `FistsView`가 정한 위치로 뻗는 절차적 동작이며, 몸 클립으로 치는 펀치는 후속 작업이다.

| 행동 | 현재 동작 | 주요 기본값 |
| --- | --- | --- |

공통 근접 검사는 한 공격 ID와 적중 목록을 유지한다. 같은 적의 여러 콜라이더나 왕복 회전으로 피해가 중복되지 않는다. 주먹·공통 근접 스윕·밀치기는 벽을 무시하고 사거리와 전방 범위 안의 적을 타격한다. 벽은 대상 수 제한을 소모하거나 스윕을 끝내지 않으며, 가드·패링은 기존대로 주먹 공격을 종료한다. 밀치기도 범위 안의 여러 명을 한 번씩 맞힐 수 있다.

주먹이 벽에 닿으면 한 공격당 벽 소리를 한 번 재생하고 후딜을 즉시 해제한다. `Combat/Player/Attack/Punch/Wall`의 10개 클립은 `Feedback`의 `Punch Wall Sounds`에 연결되어 있고, 직전에 재생한 클립을 피해서 고른다. 적 타격 소리와 벽 타격 소리는 각각 한 번만 재생한다.

V 홀드는 단일 대상 기술이다. 접근·타격·회복 중에는 이동·시점·공격·방어·회피·슬롯 변경을 잠근다. 벽, 대상 소멸, 접지 상실, 채팅·포커스 상실 등으로 취소되며, 홀드 후 놓을 때 탭 밀치기를 추가하지 않는다.

**상태별 V**([ShoveMoves](../Scripts/Player/Combat/ShoveMoves.cs), Player.csv `Shove` 행): 움직이며 누르면 위 표의 밀치기(레포데), 가만히 서서 누르면 ArcCW의 근접 도약(`sh_bash.lua` DoLunge)을 옮긴 도약 밀치기, 총을 장전하는 중이면 GMod Mighty Foot Engaged(1987521428)의 발차기다. 도약은 시선 끝의 첫 대상이 밀치기 사거리보다 멀고 `lungeLength` 안일 때만 하며, 위로는 뛰지 않는다. 발차기의 시간표·거리·피해·반동은 원본 그대로이고, 원본에 없는 밀침·경직은 "장전을 끊지 않는 밀치기"라는 요구대로 밀치기와 같게 준다. 원본의 문 열기·부수기는 옮기지 않았다(이 게임의 문은 돌진 밀치기로 부순다). 몸이 차는 동작은 Beatrun의 `kick` 클립(왼발 앞차기, 0.33초에 가장 멀리 뻗는다)을 두 다리만 쓰는 층에서 재생하므로 팔은 장전을 계속하고, 다른 PC에서도 같은 클립이 나온다([PlayerBody.Kick](../Scripts/Player/Body/PlayerBody.Kick.cs), `PlayerNetworkCombat`).

**돌진 밀치기**([PlayerCombatActions](../Scripts/Player/Combat/PlayerCombatActions.cs), Player.csv `Ability.dashPush*` 행, Dynamic Landing의 Push): 총을 들었든 빈손이든 시선 쪽으로 `dashPushMinSpeed`(5m/s) 이상 달리며 V를 누르면 `dashPushDuration`(0.25초) 동안 그때 속도의 `dashPushSpeedScale`(2)배로 돌진한다. 몸 앞 `dashPushReach`(0.5m)에 처음 들어온 적에게 피해·체간 피해(각 20)를 주고 그 자리에서 멈춘다. 쌓인 달리기 속도도 출발 속도로 깎인다. 맞은 적은 돌진 속도로 밀려 날아가며 `dashPushThrowTime`(0.5초)에 걸쳐 느려지고(그동안 부딪힌 적에게 밀치기 연쇄가 넘어간다), 끝에서 넘어져 `dashPushKnockdownDuration`(1.5초) 동안 누워 있다([MeleeCombatTarget](../Scripts/Combat/Damage/MeleeCombatTarget.cs)`.Barge`). 큰 적(`Large`)이나 막아 낸 적은 군중 밀치기처럼 밀리기만 한다. 벽 너머의 적은 맞지 않고, 가벼운 프랍은 몸으로 차 내며, 문은 `doorBreakSpeedThreshold` 이상이면 부순다. 빗나가면 원래 달리기 속도로 이어 간다. 끝난 뒤 `dashPushCooldown`(1초) 동안 V는 평소의 V다. 몸은 `Body.dashPush`(bargein)를 재생하고, 적에게 멈추면 그 클립을 끝까지 재생한다. 소리는 `DashPush`(시작)·`DashPushHit`(Dynamic Landing push1-4) 큐다. 달리지 않을 때의 V(총: 군중 밀치기, 빈손: 탭 밀치기·홀드 가드 브레이크)는 그대로다. 가드 브레이크로 다가가는 중에는 돌진하지 않는다.

밀치기 소리는 첫 접촉에 한 번 재생한다. 적 접촉을 벽 소리보다 우선하고, 적중하지 않은 허공에서는 소리가 없다. 슬라이딩 접촉은 `SlideCombat`이 독립적으로 처리한다. **저스트 슬라이드와 몸 크기별 반응·실제 레그돌은 [이동 안내](MovementGuide.md)를 따른다.**

## 4. 가드·패링·완벽 방어

### 가드와 가변 패링

주먹 상태의 우클릭은 전방 **150도**의 방어 가능한 일반 근접 공격을 막는다. 후방·낙하·총알·방어 불가 공격에는 적용하지 않는다. 패링 창은 세키로의 튕겨 내기 규칙을 그대로 옮겼다(Fextralife 위키 Deflection: 기본 12프레임, 최근에 가드를 놓았다 다시 누를 때마다 줄어 4프레임, 너무 빠른 연타는 0프레임, 30프레임 쉬거나 튕겨 내면 회복).

| 설정 (Player.csv `Fists`) | 기본값 | 의미 |
| --- | --- | --- |
| parryWindowDurations | 0.2 / 0.133 / 0.067 / 0초 | 누른 순간부터 튕겨 낼 수 있는 시간. 성공 없이 놓았다 곧 다시 누를 때마다 다음 값. 0은 막기만 |
| spamResetDelay | 0.5초 | 가드에서 손을 뗀 채 이만큼 지나면 가장 넓은 창으로 복귀 |
| guardInputBuffer | 0.12초 | 실행할 수 없는 행동 중 새 방어 입력을 잠시 보관 |
| guardMoveShare | 0.5 | 가드를 들고 있는 동안 걷는 속도의 이 배율까지만 움직인다. 가드를 들고 다니는 남발을 막는다 |
| parryRootSeconds | 0.15초 | 패링 히트스톱이 끝난 뒤에도 발이 묶이는 시간(역경직). 주먹·가드·회피는 바로 된다 |
| 패링 효과 | 체간 25, 기절 0.8초 | 한 입력에서 한 번 적용 |

- 가드·패링 성공 또는 피격 시 반복 입력 단계를 초기화한다. 단계가 좁아져도 가드 입력 자체를 잠그지 않는다.
- 패링에 성공하면 그 자리에서 멈춘다. 히트스톱(아래) 동안 시간과 함께 멈추고, 끝난 뒤 `parryRootSeconds` 동안 다리만 묶인다. 걷는 속도는 이동 쪽 `LocomotionState`가 `PlayerMeleeCombat.LimitMoveSpeed`로 묻는다.
- 짧게 눌렀다 놓아도 남은 패링 창은 유지한다. 버튼을 계속 누르면 패링 창이 끝난 뒤 일반 가드로 이어진다.
- 방어는 주먹 차징·공격·밀치기 후딜을 취소한다. 회피·가드 브레이크 등 독점 행동이 끝날 때까지 오래 홀드한 입력은 일반 가드로 복귀하며 새 패링으로 처리하지 않는다.

### 패링 성공 표현

일반 패링에는 슬로모션을 걸지 않는다. 효과를 한 번에 터뜨리지 않고 시간차로 쌓아 화려하되 깔끔하게 보이게 한다. 주먹 패링에는 금속음이나 번개처럼 주먹과 어긋나는 표현을 쓰지 않는다. [ParryFeedback](../Scripts/Player/Combat/ParryFeedback.cs)이 `HitResolved`의 `Parried`를 듣고 한 순간에 맞춰 아래를 실행한다. 수치는 Player.csv의 `Parry` 행이다.

| 층 | 동작 | 위치 |
| --- | --- | --- |
| 손 | 공격자 반대쪽 손이 0.04초에 화면을 가로질러 뻗고, 히트스톱 동안 멈췄다가 빠르게 풀린다 | [FistsView](../Scripts/Player/Combat/FistsView.cs) `Deflect` |
| 시간·화면 | 0.2초 히트스톱(체간 붕괴 0.25초), 실제 시간으로 들어가는 화면 충격과 줌, 밝기·색수차·렌즈 펄스. 펄스는 히트스톱 동안 유지했다가 시간이 풀릴 때 함께 사라진다 | `CombatTimeEffects`, `CameraViewPunch.ImpactPunch`, `KillConfirmEffect.Parry` |
| 빛 | 플레어 → 타격 이펙트와 주황 별(0.01초) → 불꽃(0.06초) → 잔불(0.12초). 타격 이펙트와 별은 Feedback의 `Parry Hit Effect`, `Parry Sparkle Effect` 프리팹이고 비우면 나오지 않는다. 어느 팩의 프리팹이든 넣어 볼 수 있으며, 프리팹에 붙은 소리는 재생되지 않는다 | [ParryVfx](../Scripts/Combat/Feel/ParryVfx.cs), `Prefabs/Effects/Parry` |
| 적 | 몸이 하얗게 번쩍이고, 뒤로 밀리며 휘청이다 멈춘다 | `HitFlashRenderer.WhiteFlash`, `MeleeCombatTarget.ReceiveShove`, [EnemyParryRecoil](../Scripts/Combat/Feel/EnemyParryRecoil.cs) |

3초 안에 이어지는 패링은 최대 4단계까지 음이 1.5반음씩 오르고 효과가 커진다. 패링으로 체간을 무너뜨리면 효과와 충격이 가장 커지고, 화면 색이 빠지며 십자 플레어와 붉은 잔불이 나오고, `Parry Break Sounds`가 재생된다. 타격 이펙트 위로 처형 아이콘과 같은 모양인 검은 먹(`Parry Break Ink Effect`, 0.02초)과 붉은 베기(`Parry Break Slash Effect`, 0.035초)가 겹친다. 베기가 분홍으로 씻기지 않도록 `Parry.breakSaturation`은 -40 안쪽으로 둔다. 이때 체간 붕괴 히트스톱(0.25초)이 끝난 뒤 기본 0.35초 동안 0.3배속이 되어 처형으로 이어지는 순간을 강조한다(빠진 색은 둘을 합친 동안 유지된다). 처형을 시작하면 바로 끝나며, 값은 Player.csv의 `Defense` 행이다.

처형할 수 있는 적은 몸 전체에 옅은 붉은 기운이 돌고 붉은 외곽선이 생긴다. [ExecutableHighlight](../Scripts/Combat/Feel/ExecutableHighlight.cs)가 `CanExecute`를 보고 켜며, 그리기는 `HitFlashRenderer`의 오버레이가 맡는다. 색과 두께는 Feedback의 `Executable Body`다.

### 패링 타이밍

적의 타격은 예고음이 시작되고 Enemies.csv의 `windup`초 뒤에 들어온다. 소리 길이와는 무관하다. 패링 창은 키를 누른 순간부터 `Fists.parryWindowDurations`의 첫 값(0.2초)만큼 열린다. 따라서 타격보다 최대 0.2초 먼저 누를 수 있고, 예고음 시작 뒤 0.25~0.45초에 누르면 튕겨 낸다.

타격을 예고음 끝에 맞추면 안 된다. 현재 예고음은 0.89초 길이지만 0.1~0.33초에 가장 크고 이후 사그라든다. 플레이어는 큰 소리를 듣고 0.2~0.3초에 누르므로, 타격이 소리 끝에 오면 창이 먼저 닫혀 "일찍 누른" 느낌이 든다. 그래서 `windup`은 소리가 꺾이는 0.45초로 둔다. 공격 주기는 `attackInterval + windup`이므로 `windup`을 바꿀 때 `attackInterval`도 함께 맞춘다.

### 완벽 회피와 반격

실제 공격을 회피 무적 또는 회피 궤적 검사로 피하면 완벽 회피가 성립한다. 패링의 반격 창은 `Defense.parryOpensCounter`로 켜며, 반격 스킬이 생기기 전에는 꺼 둔다. 켜면 `DamageHit.IsComboFinisher`가 표시된 **연속기의 마지막 타격**을 패링할 때 반격 기회를 연다. 단일 공격도 마지막 타격으로 취급한다.

기본 효과는 실제 시간 1초의 반격 창, 0.08배속, 푸른 비네트와 `[LMB] 반격`이다. 새 좌클릭으로, 달려들기가 시간 안에 닿는 공격자에게 반격한다(내 몸 가운데에서 상대 몸까지 `counterStopDistance` + `counterDashSpeed` × `counterDashTimeout`, 지금 5.4m). Alt로 끝까지 물러난 뒤에도 닿는다. 닿는 적이 하나도 없으면 그 클릭으로 반격 창과 슬로 모션이 바로 끝나, 클릭이 느린 시간 속 일반 주먹이 되지 않는다. 달려드는 동안에는 Alt·Q/E 회피가 나가지 않아, 반격 도중 새 완벽 회피로 슬로 모션이 다시 걸리지 않는다. 같은 반격 창에서 여러 적의 공격을 피했다면 모두 후보이고, 시선이 가장 향한 적에게 간다(1m 더 먼 것을 시선에서 `counterPickDegreesPerMetre` 10°만큼 더 벗어난 것으로 친다). 먼저 공격자에게 `Defense.counterDashSpeed`(14m/s)로 바짝 달려들어(내 몸 가운데에서 상대 몸까지 `counterStopDistance` 0.5m, 최대 `counterDashTimeout` 0.35초) 다음 주먹을 끝까지 당긴 채 붙고, 그 순간 실제 주먹을 낸다. 눈에서 상대 몸까지 `counterStrikeReach`(1.4m) 안이고 사이에 막힌 것이 없을 때만 HP 피해 80·체간 피해 60이 들어간다. 가는 길이 다른 적에게 막혀 더 다가가지 못하면 시간 초과를 기다리지 않고 바로 주먹을 내고, 눈과 상대 사이에 다른 적이 끼어 있으면 그 적이 맞는다. 벽에 막히면 빗나간다. 달려드는 동안과 주먹 뒤 0.5초는 무적이다([PlayerPerfectDefense](../Scripts/Player/Combat/PlayerPerfectDefense.cs)).

반격은 적이 있는 방향에 따라 다르게 친다. 시선에서 `Defense.elbowFromAngle`(60°) 안의 적에게는 곧은 주먹이 나간다. Q/E 회피(슬립)로 연 반격이면 슬립할 때 이미 시선이 그 공격자에게 붙어 있고(비켜 돌기, [MicroSlip](../Scripts/Player/Movement/Dodge/MicroSlip.cs)), 곧은 주먹은 달려드는 동안에도 그 적을 본다. 그보다 옆이나 뒤에 있는 적, 예를 들어 Alt 회피로 몸을 뚫고 지나가 등 뒤에 남은 적에게는 팔꿈치로 뒤를 찍는다. 조준은 그대로 둔 채 그 적 쪽 어깨 너머로 `elbowGlance`(40°)만 돌아보고(나가기 0.1초, 머무르기 0.05초, 돌아오기 0.15초), 그쪽 주먹을 가슴 옆으로 끌어당겨 팔꿈치가 뒤로 나가게 한다. 맞는 순간 그쪽 화면 가장자리가 0.14초 빛난다. 피해·체간 피해·사거리·무적은 곧은 주먹과 같다. 돌아보기, 슬립의 숙이기와 시선 고정은 [CombatHeadMotion](../Scripts/Player/Combat/CombatHeadMotion.cs)이 값을 내고 카메라와 시선이 그 값을 읽는다. 다른 사람 화면에서 팔꿈치 동작을 보여 주는 것은 아직 없다.

반격은 기존 공격·장전·회피를 정리하고 같은 입력의 일반 공격을 소비한다. 한 회피에서 여러 공격을 피하더라도 보상·반격 창을 반복 갱신하지 않고, 그 공격자들을 반격 후보에 더하기만 한다. 사용·만료·피격·사망·처형·입력 상실 시 효과를 해제한다. 일시정지는 반격 시간을 보존한다.

`CombatTimeEffects`가 반격 슬로모션과 히트스톱의 소유권을 관리한다. 개별 공격에서 `Time.timeScale`을 임의로 원상복구하면 다른 효과나 일시정지를 덮어쓸 수 있으므로 이 경로를 사용한다.

### 적 몸 통과

스텝 회피와 마이크로 회피 무적 구간에는 적 몸과 플레이어 사이의 충돌만 임시로 무시한다. 벽·지형·공격 피해 판정은 유지한다. 종료 시 몸 전체가 적 밖의 안전한 위치에 나왔는지 확인한 뒤 충돌을 복구한다. 적과 벽 사이에 갇혀 즉시 복구할 수 없는 쌍은 해소될 때까지 유지하며, 이 보정이 무적 시간을 연장하지는 않는다.

## 5. 체간·흐트러짐·처형

`MeleeCombatTarget`은 체간, 기절, 단일 대상 예약을 관리한다. 체간이 0이 되면 흐트러짐 상태를 유지하고 **체간을 모두 회복해야** 행동 가능 상태로 돌아온다. 기본 회복은 0.35초 대기 후 4초 동안 진행된다. 흐트러진 적에게 체간 피해를 더 주어도 회복 시작과 효과음을 반복 초기화하지 않는다.

처형은 시야 중심과 가까운 거리 안에 있고 벽에 가리지 않은 흐트러진 적 한 명을 대상으로 한다. 기본 선택 범위는 시야 중심 38도·충돌체 거리 2.1m다. 슬롯 선택 여부와 관계없이 F로 실행한다.

**좌클릭 인살**(세키로처럼 공격 버튼이 곧 처형): 주먹 상태에서는 흐트러진 적이 `Execution.deathblowReach`(4m) 안에 있으면 좌클릭이 주먹 대신 처형이 된다. `dashSpeed`(14m/s)로 적 몸 `dashStopDistance`(0.65m)까지 달려든 뒤(최대 `dashTimeout` 0.35초) 처형 시간표가 시작된다. 달려드는 동안도 처형 중이라 무적이고 다른 입력은 잠긴다. 패링 히트스톱 중에 누르면 히트스톱과 체간 붕괴 슬로모션을 끊고 바로 시작한다. 열린 반격 창이 있으면 같은 클릭은 반격이 먼저 가져간다.

- 기본 처형 시간은 0.8초이며 0.35초에 기존 피해·사망 경로로 즉사 타격한다. 사망 이벤트와 웨이브 집계는 유지한다.
- 처형 전체 구간에 HP·실드를 보호하고 이동·시점·공격·장전·방어·회피·슬롯 전환을 잠근다. 회피 보상은 만들지 않는다.
- 대상의 체간 회복을 예약 중 멈춘다. 타격 전 대상 소멸·비활성화, 플레이어 초기화·비활성화, 채팅·포커스 상실 시 취소하고 잠금을 해제한다.
- 같은 씬의 적은 공격 준비를 취소하고 추적·공격을 멈춘다. 가까운 정상 NavMesh 적은 벽과 이동 영역 안에서 물러나며, 기절·흐트러짐 중인 적은 움직이지 않는다.
- 정식 처형 애니메이션은 아직 없다. `PlayerExecution.Started / Impact / Ended` 이벤트에 모델 연출을 연결한다.
- 방에서는 처형한 사람의 PC가 바로 시작하고 호스트가 적을 붙잡는다. 두 사람이 한 적에게 함께 누르면 늦은 쪽이 거절되어 취소된다. 끝났다는 소식이 끊겨도 적이 영영 붙잡힌 채 남지 않도록, 붙잡은 쪽이 더는 그 적을 처형하고 있지 않으면 적이 스스로 풀리고(`MeleeCombatTarget.Tick`), 호스트의 남의 처형은 처형 시간보다 2초 넘게 소식이 없으면 끝낸다. 같은 사람이 처형 목록에 두 번 들어가지도 않는다.

### 적 머리 위

적 머리 위에 서 있으면 그 적은 위로 치지 못한다. 대신 `HeadStand.shakeDelay`(0.35초) 뒤 몸을 털어 플레이어를 서 있는 쪽 옆으로 1.1m 밀어 떨어뜨린다(살짝 튀어 오르고, 적이 기울고, 밀치는 소리와 화면 충격). 기절·흐트러짐·붙잡힘 중인 적은 털지 못한다. 그동안 주변 적은 위로 손을 뻗어, 옆 거리 `attackRange` 안이고 자기 머리 위 `reachAbove`(0.5m)까지면 친다. 이 위쪽 거리는 다른 적의 머리 위에 선 사람에게만 쓰고, 난간 위는 예전처럼 발끝끼리 잰 거리다. 판정은 모양만 보므로 호스트와 그 플레이어의 PC가 같은 답을 낸다([EnemyHead](../Scripts/Enemies/EnemyHead.cs)). 떨어뜨리기는 그 플레이어의 PC가 움직인다([HeadStandShakeOff](../Scripts/Player/Combat/HeadStandShakeOff.cs)).

HP·체간 바, 흐트러짐 표시와 처형 안내는 기존 적·프리팹에도 실행 시 연결된다. 새 적 AI를 추가할 때는 `MeleeCombatTarget.IsStunned`, 넘어짐, `PlayerExecution.Suppresses`를 존중해야 한다.

## 6. 타격감과 화면 표시

전역 설정은 [GunFeel.asset](../Resources/Combat/GunFeel.asset), 무기별 화면 킥·총성·총알 반응은 `WeaponData`의 Feel 항목이다. 방어·반격·피해 팝업·HP 손실 표시는 [Feedback.asset](../Resources/Combat/Feedback.asset)에서 조절한다. 빈 사운드 슬롯은 해당 Gun Feel 합성음을 사용한다.

| --- | --- | --- |
| 발사 | `WeaponFeedback`, 화면 킥, 탄피, 총성·장전음. 총구 화염은 [MuzzleFlash](../Scripts/Combat/Weapons/Effect/MuzzleFlash.cs), 조명은 [MuzzleLight](../Scripts/Combat/Weapons/Effect/MuzzleLight.cs) | 화면 킥과 실제 조준 반동을 구분 |
| 명중 | `GunFeelDirector`, 히트마커·확인음·혈흔·피해 팝업 | 받아들여진 피해 보고에서 표시 생성 |

**총구 조명**(326): 총구 15cm 앞의 점광원이 0.08초 동안 주변을 비춘다. 값은 GunFeel의 Muzzle light다.
- 레포데 애드온 Optimized Muzzle Flash(3605084814)에서 온 값: 범위 12.7m(500유닛), 0.08초, 색 250·150·30. 색은 Unity 색 선택기의 250·150·30, 은은한 주황이다. Source가 비추는 대로 선형 색으로 읽으면 253·202·96의 노란빛인데, 사용자가 그쪽을 덜 멋있다고 해서 주황으로 되돌렸다(2026-11-06).
- 위치: 애드온은 빛을 쏘는 사람 몸 가운데에서 50유닛 앞에 두지만, 여기서는 총구를 따라간다. 총구가 벽에 박혀 있거나 벽을 뚫고 나가 있으면 벽 앞에서 멈춰 벽 너머를 안쪽에서 비추지 않는다.
- 밝기와 위아래: 옆으로는 10이라 벽에 주황빛이 은은하게 돈다. 바로 아래와 바로 위는 절반(`muzzleLightBelow` 0.5)이고, 그 사이는 각도에 따라 이어진다(빛의 쿠키, 큐브맵). 화면에 톤매핑이 없어서 고르게 10이면 가장 가까운 면인 발밑 바닥(과 낮은 천장)이 한 가지 노란색으로 타고, 빛이 총구가 아니라 바닥에서 나는 것처럼 보였다. 3으로 낮추면 그건 사라지지만 주변이 어두워졌다(2026-11-06 사용자 테스트 두 번). 위아래만 줄이면 바닥은 총구 아래에서 멀어질수록 어두워지는 주황으로 남고 벽의 빛은 그대로다.
- 그림자: 내 총의 빛은 그림자를 내서 벽·기둥·몸이 빛을 막고, 그림자가 총구 반대쪽으로 진다. 해상도는 중간 단계(면당 512, `muzzleLightShadowTier`)로 여섯 면을 그린다. 그림자 없는 15% 세기의 빛이 하나 더 있어 그림자를 조금 채우고, 옆방에서 쏘면 벽과 문 너머로 희미하게 샌다. `muzzleLightShadows`로 그림자를 끈다.
- 다른 사람 총은 35% 세기로 그림자 없이 비춘다. 지도를 불러올 때 그림자 빛을 두 프레임 켜 두어 첫 발에 멈추지 않게 한다.
- 시간: 발사 이벤트(`ShotFired`)와 같은 프레임에 켜져 0.08초 중 앞 60%(`muzzleLightHold` 0.6, 48ms)는 최대 밝기, 나머지는 제곱으로 사그라든다. 고르신 CS2식 총구 화염([MuzzleFlash](../Scripts/Combat/Weapons/Effect/MuzzleFlash.cs))이 50ms 밝고 68ms까지 꼬리가 남으므로 거기에도 맞는다. 소총(600RPM, 0.1초 간격)으로 연사하면 빛이 80% 동안 켜져 있다. 화염 세션이 CS2 영상에서 잰 CS2의 빛은 3프레임(0.06초, Hold 0.5)이다. 한때 그 값으로 줄였지만 연사 중 빛이 절반 가까이 꺼져 있어 덜 밝아 보였다. 애드온의 빠른 깜빡임(style 4)은 전역 시각에 맞춰 깜빡여 절반의 발사가 어둡게 나오므로 옮기지 않았다.

### 크로스헤어

손에 든 것에 따라 프로필이 바뀐다. [WeaponCrosshairSelector](../Scripts/UI/Crosshair/WeaponCrosshairSelector.cs)가 무기 선택과 설정 변경을 듣고 고른다.

1. 플레이어가 설정 → 크로스헤어에서 직접 꾸민 모양. 총용과 근접용이 따로 있다([CrosshairSettings](../Scripts/Settings/CrosshairSettings.cs)).
2. 무기의 `Crosshair Profile`
3. Feedback의 `Gun Crosshair` 또는 `Melee Crosshair`
4. 그 외에는 씬의 크로스헤어에 지정된 프로필

직접 꾸미기는 [CrosshairPresets.csv](../Resources/Tables/CrosshairPresets.csv)의 프리셋이나 공유 코드에서 시작한다. 프리셋은 모양과 회전만 바꾸고 색·불투명도·테두리는 그대로 둔다. 표에 줄을 더하면 타일이 늘어나고, 두 줄을 넘으면 스크롤된다. 공유 코드는 `ENF-`로 시작하는 문자열이다([CrosshairCode](../Scripts/Settings/CrosshairCode.cs)). 새 항목은 뒤에만 붙이므로 예전 코드도 계속 읽힌다. 미리보기 오른쪽 위의 버튼을 누르고 있으면 설정창이 사라지고, 꾸미는 중인 크로스헤어가 실제 HUD에 보인다.

근접은 조준이 중요하지 않으므로 가운데가 이어진 14픽셀 붉은 X 하나만 쓴다. X 전체가 그림 한 장이고 프로필의 점 자리에 들어가며(`dotSize` 7은 14픽셀), 부품은 쓰지 않는다. 부품을 모아 X를 만들면 가운데에서 외곽선이 서로를 가린다. X 끝이 반경 10픽셀 안쪽이라 반경 15.5픽셀까지 들어오는 히트마커와 겹치지 않는다.

| 헤드샷 | 살짝 굵고 긴 금색 X와 가운데에서 반짝이는 네 갈래 별빛 | 틱 위에 짧은 금속음 |

| 가드·패링·무적 등 피해 없음 | 얇은 회색 X | 없음 |

히트마커는 기준 60fps에서 7프레임 넓게 유지 → 9프레임 동안 선을 안쪽으로 이동 → 1프레임 흐리게 표시한 뒤 사라진다. 실제 프레임률과 무관하게 같은 시간을 사용한다. 새 적중은 다시 넓은 상태로 시작하되, 막 뜬 처치 마커는 0.18초 동안 후속 일반 명중이 덮어쓰지 않는다. 막 뜬 마커는 30% 크게 시작해 0.07초 만에 제자리로 돌아오므로, 연사해도 한 발씩 구분된다(블랙옵스 6이 같은 이유로 히트마커를 고쳤다). 몸샷·헤드샷 마커의 선 길이는 그 명중이 앗아 간 체력 비율을 따른다. 스친 명중은 0.85배, 체력의 절반 이상이면 1.25배다. 체간 붕괴는 플레이어의 명중이 들어간 직후 0.25초 안에 적의 체간이 깨질 때 뜬다(`MeleeCombatTarget.AnyStaggered`). 한 프레임에 들어간 명중(산탄총의 산탄, 여러 적을 한 번에 벤 휘두르기)은 프레임 끝에 마커 하나와 소리 한 벌로 묶는다. 이때 헤드샷 표시는 그중 30% 이상이 머리에 맞았을 때만 뜬다(오버워치의 산탄 규칙, GunFeel의 `Headshot Hit Share`). 단발 명중은 그대로 헤드샷이다. 관통 꼬리는 묶인 명중 중 하나라도 관통이면 뜬다(`DamageHit.Pierced`). 꼬리에는 어두운 테두리가 없어서 두 번째 마커가 아니라 선의 잔상으로 보인다. 크기·색·시간은 GunFeel의 Hit markers에서 조절한다. 꼬리는 `Pierced Tail Length`(선 길이의 0.75배, 처음에는 그 60%)와 `Pierced Tail Alpha`(가까운 마디 0.38, 먼 마디는 그 42%)로 조절한다.

점수는 처치에만 부여한다. 크로스헤어 오른쪽 아래에 점수와 처치 사유를 표시하고 연속 처치 동안 누적한다. 처치한 총알이 벽이나 다른 몸을 뚫거나 튕겨서 왔으면 "관통 사살"이 붙는다(GunFeel의 `Pierced Bonus`, 25). 헤드샷 사유는 금색 폭발 아이콘과 함께 금색으로 표시하므로 헤드샷 처치는 마커의 추가 왕관 대신 이 줄로 구분된다. 처형은 전술 단검과 베기 자국 아이콘과 빨간색, 반격은 되돌아오는 화살표 아이콘과 반격 색(Feedback → Counter Color, 피해 팝업과 같은 색)으로 표시한다. 반격 아이콘은 Feedback의 `Counter Icon`이 지정되어 있으면 그것을 쓴다. 오른쪽 위에는 누적 XP와 킬로그가 나온다. `Score Font`, `Score Offset`, 보너스와 유지 시간을 GunFeel에서 조절한다.

히트마커와 피해 팝업은 화면 킥이 적용된 카메라를 기준으로 그려진다. 실제 조준점과 명중 대상의 연결을 유지하면서 화면 효과를 따라간다. 확인음([HitConfirm](../Scripts/Combat/Feel/HitConfirm.cs))은 살 타격음 위에 겹친다. 소리 파일은 `Art/Audio/HitConfirm`의 `Body`·`Head`·`Kill`·`Break` 폴더에 넣으면 그대로 쓰이고, 볼륨과 피치는 [Sounds.csv](../Resources/Tables/Sounds.csv)의 `HitConfirm/…` 행에서 바꾼다. 헤드샷 소리는 길게 울리는 종소리 대신 짧은 금속음이다. 연속 처치 때의 처치음 상승 폭은 GunFeel의 `Kill Streak Pitch Step`과 `Kill Streak Steps`다.

### 적 피격과 처치 효과

총알은 기본적으로 적을 밀고 잠시 감속시킨다. 헤드샷 또는 짧은 시간에 누적된 몸샷 피해가 조건을 만족하면 공격 준비를 취소하고 기절시킨다. 연속 기절에는 쿨다운이 있다. 총알의 체간 피해는 무기별 Posture Damage와 GunFeel의 헤드샷 배율을 사용한다. 체간 피해 자체가 매번 공격을 취소하지는 않으며, 체간 0에서는 흐트러짐이 된다.

피격 발광은 잠시 오버레이 재질을 추가한 뒤 제거한다. 처치 시 `CorpseTopple`은 제거되는 적의 시각 사본을 넘어뜨리고 가라앉힌다. 이 사본에는 충돌체가 없으며, 슬라이딩에 의해 살아 있는 적이 실제 물리로 넘어지는 `EnemyKnockdownPresentation`과 구분한다.

화면 전체 처치 펄스는 기본적으로 **처형·완벽 방어 반격 처치**에만 적용한다. 일반 총기 처치는 `Kill Pulse On Gun Kill`을 켰을 때 적용한다. 펄스 동안의 포스트 프로세싱은 종료 후 기존 카메라 상태로 복구한다. 각 층은 GunFeel의 Master Switches에서 개별로 끌 수 있다.

## 7. 확정된 후속 방향

아래는 이후 구현할 기획이다. 현재 게임에 연결되어 있는 기능으로 취급하지 않는다.

1. 필드 무기는 호환되는 빈 슬롯에 자동으로 들어가거나, 현재 선택한 호환 무기와 교체한다. 기존 `TryAcquire`에 필드 아이템·상호작용·드롭을 연결한다.
2. 빈 슬롯에서 궁극기를 사용하면 잠깐 시간을 멈추고, 슬롯 유형에 맞는 하위 티어 무기 3개 중 하나를 선택한다.
3. 무기를 든 슬롯에서 궁극기를 사용하면 해당 무기를 한 단계 진화시킨다.
4. 최종 진화 상태에서는 해당 무기의 고유 궁극기·스킬·버프를 사용한다.
5. 1티어 무기의 Q/E는 기존 기울이기·마이크로 회피를 유지한다. 진화 후에는 무기별 액티브로 바뀔 수 있다. 카타나 Q 찌르기·E 대시는 예시다.
6. 기본 가드 브레이크는 한 명을 대상으로 하며, 후속 스킬로 여러 적에게 기절이 퍼지도록 확장할 수 있다.

무작위 3지선다 UI, 시간 정지 선택 흐름, 티어·진화 경로, 고유 궁극기, 진화 Q/E, 다중 대상 가드 브레이크는 아직 구현되지 않았다. 기존 궁극기 게이지·초상화·불꽃 표시는 후속 시스템을 연결할 기반으로 유지한다.
